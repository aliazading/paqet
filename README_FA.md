# paqet - انتقال داده در سطح بسته‌های خام (Raw Packet)

[![Go Version](https://img.shields.io/badge/go-1.25+-blue.svg)](https://golang.org)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

ابزار `paqet` یک پروکسی (Proxy) دوطرفه در سطح بسته (Packet-level) است که با استفاده از سوکت‌های خام (Raw Sockets) در زبان Go ساخته شده است. این ابزار ترافیک را از یک کلاینت (Client) محلی به یک سرور (Server) راه دور هدایت می‌کند و از آنجا به سرویس‌های مقصد متصل می‌شود. با فعالیت در سطح بسته، این ابزار پشته TCP/IP (TCP/IP Stack) سیستم‌عامل میزبان را به‌طور کامل دور می‌زند و از پروتکل KCP برای انتقال امن و قابل اعتماد داده‌ها استفاده می‌کند.

> **⚠️ وضعیت توسعه**
>
> این پروژه در حال **توسعه فعال** است. رابط‌های برنامه‌نویسی (API)، قالب تنظیمات، مشخصات پروتکل و رابط خط فرمان ممکن است بدون اطلاع قبلی تغییر کنند. با احتیاط در محیط‌های عملیاتی استفاده کنید.

## موارد استفاده و انگیزه

ابزار `paqet` برای سناریوهای خاصی طراحی شده است که در آن VPNهای استاندارد یا تونل‌های SSH ممکن است کافی نباشند. موارد استفاده اصلی آن شامل موارد زیر است:
- دور زدن دیواره‌های آتش (Firewalls) که پروتکل‌های دست‌افشاری (Handshake) استاندارد را شناسایی می‌کنند.
- استفاده از ساختارهای بسته سفارشی برای ناشناس ماندن.
- فرار از رهگیری اتصالات در سطح هسته سیستم‌عامل (Kernel-level connection tracking).

## نحوه کارکرد

ابزار `paqet` یک کانال انتقال با استفاده از KCP بر روی بسته‌های خام TCP ایجاد می‌کند و پشته TCP/IP سیستم‌عامل را به‌طور کامل دور می‌زند. این ابزار بسته‌ها را با استفاده از `pcap` دریافت کرده و بسته‌های TCP دست‌ساز حاوی داده‌های رمزگذاری شده را تزریق (Inject) می‌کند.

```
[اپلیکیشن شما] <------> [کلاینت paqet] <===== بسته خام TCP =====> [سرور paqet] <------> [سرور مقصد]
(مثلاً مرورگر)        (localhost:1080)        (اینترنت)          (آی‌پی عمومی)     (مثلاً google.com)
```

سیستم در سه لایه عمل می‌کند: تزریق بسته خام TCP، انتقال رمزگذاری شده (KCP) و مدیریت چندین اتصال در سطح اپلیکیشن (Connection Multiplexing).

پروتکل KCP ارتباطی قابل اعتماد و رمزگذاری شده را فراهم می‌کند که برای شبکه‌های با افت بسته (Packet Loss) بالا بهینه شده است.

## شروع به کار

### پیش‌نیازها

کتابخانه‌های توسعه `libpcap` باید روی هر دو ماشین کلاینت و سرور نصب شده باشند:
- **دبیان/اوبونتو (Debian/Ubuntu):** `sudo apt-get install libpcap-dev`
- **ویندوز (Windows):** نصب Npcap از سایت [npcap.com](https://npcap.com/).

### ۱. دانلود برنامه

نسخه کامپایل شده مناسب سیستم‌عامل خود را از صفحه **Releases** پروژه دانلود کنید.

### ۲. تنظیمات اتصال

برنامه `paqet` از یک فایل تنظیمات YAML استفاده می‌کند. شما باید نقش (Role) را به عنوان `client` یا `server` تعیین کنید.

#### پیدا کردن مشخصات شبکه

شما به نام کارت شبکه (Interface Name)، آی‌پی محلی (Local IP) و مک‌آدرس (MAC Address) روتر/گیت‌وی خود نیاز دارید.

**در لینوکس:**
1. **پیدا کردن کارت شبکه و آی‌پی:** دستور `ip a` را بزنید. نام کارت شبکه (مثل `eth0` یا `ens3`) و آی‌پی آن را یادداشت کنید.
2. **پیدا کردن مک‌آدرس گیت‌وی:** ابتدا آی‌پی گیت‌وی را با `ip r | grep default` پیدا کنید، سپس با دستور `arp -n <gateway_ip>` مک‌آدرس آن را ببینید.

#### تنظیمات سرور (Server Configuration)

فایل `config.yaml` را برای سرور بسازید:

```yaml
role: "server"
log:
  level: "info"
listen:
  addr: ":9999" # پورت گوش دادن سرور
network:
  interface: "eth0" # نام کارت شبکه سرور (تغییر دهید)
  ipv4:
    addr: "1.2.3.4:9999" # آی‌پی عمومی سرور و پورت
    router_mac: "aa:bb:cc:dd:ee:ff" # مک‌آدرس گیت‌وی سرور
transport:
  protocol: "kcp"
  kcp:
    block: "aes"
    key: "یک-کلید-سری-بسیار-قوی" # باید با کلاینت یکی باشد
```

#### تنظیمات بسیار مهم دیواره آتش (Firewall) سرور

از آنجا که `paqet` سیستم‌عامل را دور می‌زند، هسته لینوکس ممکن است سعی کند اتصالات را قطع کند. **باید** این دستورات را در سرور اجرا کنید:

```bash
# پورت 9999 را با پورت سرور خود جایگزین کنید
sudo iptables -t raw -A PREROUTING -p tcp --dport 9999 -j NOTRACK
sudo iptables -t raw -A OUTPUT -p tcp --sport 9999 -j NOTRACK
sudo iptables -t mangle -A OUTPUT -p tcp --sport 9999 --tcp-flags RST RST -j DROP
```

#### تنظیمات کلاینت (Client Configuration)

فایل `config.yaml` را برای کلاینت بسازید:

```yaml
role: "client"
log:
  level: "info"
socks5:
  - listen: "127.0.0.1:1080" # آدرس پروکسی برای استفاده در مرورگر
network:
  interface: "en0" # نام کارت شبکه کلاینت (تغییر دهید)
  ipv4:
    addr: "192.168.1.100:0" # آی‌پی محلی کلاینت (پورت 0 بماند)
    router_mac: "aa:bb:cc:dd:ee:ff" # مک‌آدرس مودم/روتر شما
server:
  addr: "1.2.3.4:9999" # آی‌پی عمومی سرور شما
transport:
  protocol: "kcp"
  kcp:
    block: "aes"
    key: "یک-کلید-سری-بسیار-قوی" # دقیقاً مشابه سرور
```

### ۳. اجرای برنامه

برنامه را با دسترسی روت (Root) اجرا کنید:

**در سرور:**
```bash
sudo ./paqet run -c config.yaml
```

**در کلاینت:**
```bash
sudo ./paqet run -c config.yaml
```

### ۴. تست اتصال

پس از اجرا، می‌توانید پروکسی SOCKS5 را تست کنید:

```bash
curl -v https://httpbin.org/ip --proxy socks5h://127.0.0.1:1080
```

اگر آی‌پی سرور شما در پاسخ نمایش داده شد، یعنی همه چیز درست کار می‌کند.

## دستورات دیگر

| دستور | توضیح |
| :--- | :--- |
| `run` | اجرای اصلی پروکسی کلاینت یا سرور |
| `secret` | تولید یک کلید سری امن برای بخش `key` |
| `ping` | تست اتصال ساده به سرور |
| `version` | نمایش نسخه برنامه |

## نکات امنیتی

امنیت این سیستم به کلید سری (Secret Key) شما بستگی دارد. از دستور `paqet secret` برای تولید یک کلید قوی استفاده کنید و آن را محرمانه نگه دارید. این ابزار دیواره‌های آتش معمولی مثل `ufw` را دور می‌زند، بنابراین مدیریت پورت‌ها را با دقت انجام دهید.
